# 04 · 经典输入分类规则（六类）

> **用途**：任何人（或 AI）给来一段社区服务信息，都必须能被**逐条拆开、精准归入下列六类**，并且**原文零改写**。
> **这六类是定死的**：`服务对象` · `服务事项` · `时间地点` · `行动步骤` · `注意事项` · `图形素材`。
> **上游**：课堂任务说明的"经典输入"（`text.pdf` 第四项）。
> **下游**：本文件直接喂给工作流程图的两个节点 —— **N1 输入包清点（intake.md）** 与 **N3 事实结构化（fact-table.md）**。
> **落地位置**：作为 Skill 的 `references/01-classic-input-taxonomy.md` 打包进技能包。
> **版本**：v1.0

---

## 0. 六类是什么（一句话定义 + 判定问题）

| # | 类别 | 一句话定义 | 判定问题（答"是"即归此类） | 典型信号词 |
|---|---|---|---|---|
| 1 | **服务对象** | 谁适用、谁不适用、需要什么资格 | 这句话在回答"**谁**能享受 / 谁需要看"吗？ | 面向、适用于、对象、居民、老年人、儿童、户外工作者、孕产妇、残障人士、新市民、持证、年满、限本社区 |
| 2 | **服务事项** | 提供什么服务、办什么事、包含什么内容 | 这句话在回答"**提供什么**"吗？ | 提供、开放、办理、发放、接种、体检、随访、咨询、维修、回收、招募、预约、登记 |
| 3 | **时间地点** | 什么时候、在哪里、多久一次、有效期到何时 | 这句话在回答"**何时 / 何地**"吗？ | 时间、日期、每日、每周、时段、上午/下午、开放、关闭、地点、地址、中心、驿站、阅读室、窗口、楼层、有效期 |
| 4 | **行动步骤** | 居民要做什么、按什么顺序做 | 这句话在回答"**要做什么、先做什么**"吗？ | 动词开头：饮水、遮阳、防晒、休息、洗手、关阀、开窗、登记、携带、出示、预约、拨打；顺序词：先、然后、最后、第一步 |
| 5 | **注意事项** | 禁止、风险、限制、免责、求助口径、要带什么 | 这句话在回答"**别做什么 / 要小心什么 / 出问题找谁**"吗？ | 禁止、严禁、不得、请勿、注意、谨防、风险、如出现……请……、以免、否则、免责、咨询电话、求助、报警 |
| 6 | **图形素材** | 可用的视觉素材与视觉规范 | 它是**图片 / 图标 / 标志 / 色值 / 字体 / 示意图**吗？ | 照片、插画、图标、标识、Logo、色卡、色值、字体、示意图、地图、底图、二维码 |

## 1. 识别流程（照这个顺序问，30 秒能定一条）

```
一条原始信息
  ├─ ① 它是"素材/规范"而不是"文案"吗？ ──是──▶ 图形素材
  ├─ ② 句中有"时间"或"地点"标记吗？ ────是──▶ 时间地点（主归）
  ├─ ③ 是动词开头的祈使句吗？ ──────────是──▶ 行动步骤（主归）
  ├─ ④ 含禁止 / 风险 / 求助 / 免责词吗？ ─是──▶ 注意事项（主归）
  ├─ ⑤ 讲的是"某类人群"吗？ ───────────是──▶ 服务对象（主归）
  └─ ⑥ 以上都不是，且讲"提供什么" ─────────▶ 服务事项（兜底类）
```

**为什么是这个顺序**：`图形素材`先判（材质优先于文字）；`时间地点`先于`行动步骤`（"每日 10:00-20:00 开放"是时间信息，不是让居民执行的动作）；`注意事项`先于`服务对象`（"老年人请加强防护"既含人群又含风险提示，主归看它决定海报位置）。

## 2. 歧义仲裁规则（"精准"就靠这六条）

### 规则 1｜主归 / 副归：一句话可以进两个桶，但只有一个"主归"
- **主归**＝决定这句话在海报上**占哪个位置**的类别；**副归**＝记录下来但不单独占位。
- 判断主归的问题：**"如果海报上只能放一个位置，它放哪？"**

### 规则 2｜同一句含多个信息项 → 能拆则拆
- 拆成**原子行**，每行保留**逐字原文片段**（允许截取，**不允许改写**），并用 `来源句ID` 标出它们来自同一句。
- 例：`清凉服务点：社区服务中心、东门驿站、滨河阅读室。每日 10:00-20:00 开放。`
  → 拆成两行：`服务点清单`（主归：服务事项，副归：时间地点）+ `开放时间`（主归：时间地点）。

### 规则 3｜电话怎么归
| 语境 | 主归 |
|---|---|
| "咨询电话 / 求助电话 / 如遇紧急情况请拨打" | **注意事项**（求助口径） |
| "预约电话 / 服务热线 / 报名电话"（服务入口） | **服务事项** |
- 两种语境同时存在时，**拆成两行**，不要合并。

### 规则 4｜三桶之外的收纳区（不计入六类完整性检查）
- `机构标识`（如"社区健康与服务中心"）→ 归 **图形素材**（视觉素材白名单），并在 `metadata` 里登记机构全称中英。
- `主标题 / 标语`、`落款 / 发布主体`、`发布日期 / 版本` → 归 **metadata 容器**，**不算六类之一**。
- 六类之外的**任何业务信息**（无法判定）→ 进 `unclassified` 桶，**必须**标记 `NEEDS_HUMAN`，**严禁**硬塞进六类。

### 规则 5｜缺类必须显式写"无"
- 六类中某一类**一条都没有**时，写 `无` 并登记到 `needs-human.md`，写明**影响**（例：缺"时间地点"→ S1/S3 骨架的核心字段缺失 → **不得出图**）。
- **禁止静默省略**：空白和"无"是两件事。

### 规则 6｜归类 ≠ 改写
- 归类只允许**搬运与截取**；标点、空格、大小写、全半角一律保持原样。
- 特别提醒：中文全角 `，。：、`；英文半角 `,.:`；连字符统一 ASCII `-`；`每日 10:00-20:00 开放。` 中的空格是原文，**不得删**。

## 3. 逐条映射示例（用 `text.pdf` 高温主题的 9 个信息项验证一遍）

| 原文（逐字） | 主归 | 副归 | 说明 |
|---|---|---|---|
| `社区健康与服务中心` | 图形素材 | 服务事项 | 机构标识 → 走视觉素材白名单，同时登记 metadata 机构全称 |
| `高温天气健康防护与清凉服务` | metadata（主标题） | — | **不是六类之一**；它是主视觉文案 |
| `高温预警期间，请减少非必要户外活动。` | 注意事项 | 行动步骤 | 前半句是**触发条件**，后半句才是动作 → 主归看"它决定海报位置" |
| `规律饮水。` | 行动步骤 | — | 动词开头，纯动作 |
| `外出时做好遮阳与防晒。` | 行动步骤 | 图形素材 | 需要"遮阳 / 防晒"图标 → 副归触发素材需求 |
| `老年人、儿童和户外工作者请加强防护。` | 服务对象 | 行动步骤 | 三个受众 + 一个动作；受众信息不可丢 |
| `如出现头晕、恶心或明显不适，请及时休息并寻求帮助。` | 注意事项 | 行动步骤 | 免责 / 求助口径 |
| `清凉服务点：社区服务中心、东门驿站、滨河阅读室。每日 10:00-20:00 开放。` | 时间地点 | 服务事项 | 拆两行：服务点清单 + 开放时间 |
| `咨询电话：400-123-2026` | 注意事项 | — | 求助口径（见规则 3） |

**完整性结论**：六类**全部有**（服务对象 1 · 服务事项 1 · 时间地点 1 · 行动步骤 4 · 注意事项 3 · 图形素材 1）；metadata 2 条（主标题、机构标识）；`unclassified` 0 条。

## 4. 输出格式（两种，都是机器可读）

### 4.1 `intake.md`（N1 输入包清点 · 只做分类，不做解释）

| 序号 | 类别 | 原文（逐字） | 主归 | 副归 | 来源句ID | 缺失/存疑 |
|---|---|---|---|---|---|---|
| 1 | 服务对象 | `老年人、儿童和户外工作者请加强防护。` | 服务对象 | 行动步骤 | S-06 | — |
| … | … | … | … | … | … | … |

**六类完整性检查（必须逐类打勾）**：☐ 服务对象 ☐ 服务事项 ☐ 时间地点 ☐ 行动步骤 ☐ 注意事项 ☐ 图形素材
**缺类登记**：`类别 → 影响 → 责任人 → 截止时间`

### 4.2 `fact-table.md`（N3 事实结构化 · 分类之后才做字段化）

| 类别 | 字段 | 内容（逐字） | 官方来源 | 需人类确认 |
|---|---|---|---|---|
| 服务对象 | 适用人群 | … | … | ☐ |
| 服务事项 | 服务名称 / 内容 | … | … | ☐ |
| 时间地点 | 时间 / 地点 / 有效期 | … | … | ☐ |
| 行动步骤 | 步骤 1…N（动词开头） | … | … | ☐ |
| 注意事项 | 禁止 / 风险 / 求助 / 免责 | … | … | ☐ |
| 图形素材 | 素材清单 / 图标需求 / 授权 | … | … | ☐ |

### 4.3 六类 → 海报信息层级的映射（设计侧对照）

| 类别 | 在海报上通常落在哪 | 对应版式骨架 |
|---|---|---|
| 服务对象 | 标题下的一句话"面向谁" | S1 / S3 |
| 服务事项 | 主体第一块（做什么） | S1 / S3 / S4 |
| 时间地点 | 主体第二块（时间 + 地点，四宫格或时间轴） | S1（核心） |
| 行动步骤 | 主体第三块（编号步骤） | S2（核心） |
| 注意事项 | 底部提示条 + 求助电话 | S5 / S9 |
| 图形素材 | 全图图标系统与底图 | 全部 |

## 5. 给 AI 的调用指令（可直接粘贴）

```text
你现在执行「经典输入分类」。规则见 references/01-classic-input-taxonomy.md。

对我的输入，逐条输出下表，不要解释、不要改写、不要补充我没说的信息：
| 序号 | 类别 | 原文（逐字） | 主归 | 副归 | 来源句ID | 缺失/存疑 |

硬规则：
1. 六类固定为：服务对象 / 服务事项 / 时间地点 / 行动步骤 / 注意事项 / 图形素材。
2. 归类只允许搬运与截取，标点、空格、全半角必须与原文一致。
3. 一句含多项时拆成原子行，用「来源句ID」标明同源。
4. 判不准的进 unclassified 并标 NEEDS_HUMAN，严禁硬塞进六类。
5. 六类中缺哪类，显式写「无」并写明影响。
最后给一行完整性结论：六类各有几条 + 缺哪类 + 是否可进入 N3。
```

## 6. 反模式（最常犯的五件事）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 把"注意事项"当成"行动步骤" | 海报变成一堵说教墙，居民抓不到动作 | 先问"这是**让做**还是**别做/小心**" |
| 把"服务事项"当成"服务对象" | 资格条件丢失，不该来的人来了 | 人群词 → 服务对象；服务动词 → 服务事项 |
| 把"高温预警期间"当成一个信息项 | 触发条件被拆散，读者不知道前提 | 触发条件随**主句**一起走，进"注意事项" |
| 归类时顺手润色（"请减少"→"减少"） | 母本被改写，Gate 2 直接否决 | 归类 ≠ 改写，只搬运 |
| 缺类不写"无" | 交付时才发现缺时间地点，返工 | 缺类显式登记 + 写明影响 |

---

## 7. 一页纸结论

1. **六类定死**：服务对象 · 服务事项 · 时间地点 · 行动步骤 · 注意事项 · 图形素材。
2. **一条一主归**，可以带副归；判不准就进 `unclassified` 并抛 `NEEDS_HUMAN`。
3. **归类不改写**，标点空格全保留；同句多项**拆原子行**。
4. **主标题 / 落款 / 日期 / 机构标识** ≠ 六类，走 `metadata` 与素材白名单。
5. 六类完整性是 **N1 的交付标准**；缺"时间地点"或"服务事项"时**不得出图**。
